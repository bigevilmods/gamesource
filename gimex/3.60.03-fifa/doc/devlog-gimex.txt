			Gx -ma<n> to select colour reduction module to use for art with alpha channels.  Normally the colour reduction logic will use 4D Wu for art with alpha channels.  But several other modules are available that can support alpha channels, and may be faster or better quality for your type of art.  Bond found Fu (-m2) worked better for their particular art, but wanted to use Wu for opaque art.  So they passed the art thru the pipeline twice using an -if statement based on alpha.  But this is slow and tedious.  GX colour reduction already has the ability to detect alpha and use Wu or 4D Wu, so the hardcoded 4D Wu was replaced with an optional setting.  The overall logic goes like this:
    			Criteria                          Method
	  			Less than 256 colours             Exact
				More than one transparent colour  4D Wu
				One transparent colour and 555    Wu5
  			    One transparent colour            Wu6

            This is a minor release because gimex.h changed, potentially affecting code compiled against it.

            gimex.h ggeti/ggetm - reimplemented 3 byte fetch to be Bounds Checker/Purify safe.  Used to fetch 4 bytes and do a shift (for performance).  But this could read off the ends of memory blocks & arrays, causing exceptions.  3 byte reads don't occur very often, and when they do, its usually not high performance code, so the performance hit should not be substantial overall.
            GSH - 5a3 - adjusted the threshold for opaque from 0xe0 to 0xec to take into account rounding.  The formula is a3=(a8*7+128)/255.  Solving for a8 with a3=7 you get values of 236 and lower are translucient, and 237 and higher are opaque.  With only 3 bits, rounding is very important.

                    4        146   128..163     36    10010010
                    5        182   164..200     37    10110110
                    6        219   201..236     36    11011011
                    7        255   237..255     19    11111111
            AVI - q80 by default to avoid q100 bug MVLZ and set a more reasonable default compression, consistant with jpeg

                FOURCC  BPP
                MVJP    24 bpp. EA BlackBox Motion Jpeg using Intel Jpeg.
                MVLZ    24 bpp. EA BlackBox lossless 24.  Accepts qfactors where q100 is slow but produces better compression and q40 is the fastest but least amount of compression

              Heres the new PSX colour logic: (pseudo representation)
                ARGB           PSX
                0xFFrrggbb   0x0rgb    opaque rgb
                0x80rrggbb   0x8rgb    semi-transparent  r=(rr*31+128)/255
                0x00xxxxxx   0x0000    transparent
                0xFF000000   0x0001    opaque black maps to blue
                0x80000000   0x8000    semi-transparent black
              Special cases for opaque black and transparent.
              These are proper for semi-transparent draw modes.  If you want regular draws and pure black, you can trick gx/p2 to doing it by using the colour:
                alpha   128
                red     0
                green	0
                blue	0
                or 0x80000000
                which maps to 0x8000 which is opaque black when semi-transparency is off.
